## Grid and Carousel

The projects are displayed in a grid of "cards", or compact tiles containing basic information about each project.
This allows the user to see many projects all at once and to be drawn to whatever catches their eye.

Hovering (with a mouse) or tapping (with a stylus or finger) on a project card expands it to show slightly more detail,
such as a brief summary or media item thumbnails (which can be clicked for full-screen viewing).

Clicking/tapping an expanded project card opens a popover dialog with detailed, long-form information about the project.
This popover is one of many in a "carousel" display that provides buttons for easily moving to the previous or next project's details.
Below the carousel, a row of buttons (or, on narrower devices, a slider) allows the user to jump quickly to any project.

When the user navigates to a different project's details, the corresponding project card is automatically expanded and,
if necessary, scrolled to in the background. That way, the "active" project' grid card is always in view whenever the user
closes the carousel, avoiding disorientation and confusion.

The URL automatically syncs with the current open project details so that it is easy to share a link to a specific project's details.


## Filters (with Zustand!)

Filtering the projects is straightforward. The range of years can be restricted with a slider, and the tags and categories
can be toggled with designated buttons.

To maximize shareability, the filter combinations are synced with the URL (in both directions), so that users can share or bookmark
links to specific filter configurations.

I used Zustand stores to maximize reactivity while minimizing unnecessary recomputation.


## Animation

I used a combination of CSS transitions and GSAP-driven animations to animate the project browser. 
To keep the interface responsive even with rapid input sequences (button clicks, hovering, scrolling, etc.),
I studied and made use of <Details content={
  <span>Namely, <code>useTransition</code>, <code>Suspense</code>, <code>useDeferredValue</code>, and some custom React hooks providing debouncing and throttling.</span>
}>many React framework features</Details> geared towards this.

I noticed that the animation of the collapsing/expanding project cards in the grid was causing the grid to "jump" in scroll position when one of the items at the
bottom of its column collapsed from the expanded state. This was because the height of the grid was decreasing. So, I added an extra element to the bottom of the
grid that would "reserve" the height of the tallest hidden expanded content, so that the overall height of the grid would not change when items expanded/collapsed.
To keep this reserved height up-to-date even after window resizing or filtering changed the items and/or their height, I remeasured after changes to the set
of visible projects and also configured a `ResizeObserver` to update when the width of the project browser's container changed.

I also noticed that the carousel was laggy due to loading and rendering all of the carousel cards' content, which slowed the animation when navigating the carousel.
Thus, the carousel displays a placeholder on each card and only loads the real content after a delay (to put it simply). On narrower devices, the carousel "dot" buttons
are replaced by a slider. The aforementioned and other optimizations allow the carousel to respond smoothly as the user drags the slider.

I also used state variables to pause or defer certain operations during animation (ex. project card expanding/collapsing) and/or user interaction (ex. scrolling).
